# Contributing to HubPanel

HubPanel welcomes code, documentation, translations, accessibility improvements, bug reports, and design feedback. Turkish and English contributions are welcome.

The project has an initial local UI preview and a tested database/security foundation. It is not production-ready. See [Development](docs/DEVELOPMENT.md) for setup and test commands. Read the [README](README.md), [project status](PROJE-DURUMU.md), and [roadmap](04-Fazlar/00-yol-haritasi.md) before starting.

## Propose a change

- Use GitHub Issues for bugs and proposals and pull requests for changes. Discuss major changes before investing in implementation.
- Explain the problem, expected behavior, and scope. For bugs, include reproducible steps and sanitized environment details.
- Keep pull requests focused. Describe what changed, why, and how you checked it. For documentation, check links and consistency. Once application tooling exists, run its documented checks.
- Use synthetic data in examples and screenshots. Never include credentials, private server details, customer data, or local reference copies.
- Write HubPanel implementation code independently; follow [AGENTS.md](AGENTS.md). Do not copy the local research panels into production code.
- Disclose new dependencies and their licenses. Submit only material you have the right to contribute.

## License and credit

Contributions submitted for inclusion in HubPanel are provided under the project's [MIT License](LICENSE). Contributors retain copyright in their own contributions. Third-party notices must be preserved.

Using HubPanel does not require a contribution, payment, star, or public release of your modifications. Contributions, attribution links, and sharing your experience are appreciated and voluntary. Git history and release notes can acknowledge contributors as the project develops.

## Respectful collaboration

Keep discussions constructive and focused on the work. Harassment, personal attacks, and disclosure of private information are not welcome. Maintainers may moderate discussions and decline changes outside the project's scope.

## Security and contact

Report security vulnerabilities privately using [SECURITY.md](SECURITY.md), not a public issue.
